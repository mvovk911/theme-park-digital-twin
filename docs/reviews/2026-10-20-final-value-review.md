# Closing independent value and architecture assessment

20 October 2026. This assessment closes the requested recurring user-value review of the FOX-inspired development cycle. It synthesizes repository documentation and the [dated independent reviews](README.md); it adds no application changes, new tests or live service checks. Actual GPU/browser feature evidence identifies application release `afa84a17d6cc282ed2aa4003743d62770644ea48`. The fixed API experiment uses its separately identified earlier release. Final eight-hour counts, GPU completion and resource shutdown belong to the separate numerical/operational report and are not asserted here.

**The project now supports a credible, inspectable operations demonstration. Its strongest next step is one real maintenance workflow pilot. Park-wide optimization, autonomous operating authority and measured business value remain unproved.**

## Decisions it can usefully support

The duty manager can investigate an affected asset, distinguish current observations from stale or historical evidence, inspect dependencies and prepare a maintenance request. The direct incident path avoids making an obvious inspection request depend on a forecast. It freezes the relevant source observations, rechecks current conditions before execution, retains request identity across retries and reads back the accepted work order. The ride remains closed: acceptance is not repair or permission to reopen.

The Decision Lab can compare do-nothing, simple-rule and candidate responses over a synthetic 15–120-minute horizon. Delayed staffing, replenishment, routing and other supported scenario assumptions expose waiting, served demand, remaining backlog, resource cost and adverse sensitivity cases. Saved observations, assumptions and model identity make comparisons reviewable. These are uncalibrated model experiments, not forecasts validated against park operations; an apparently best branch is a review option, not authority to act.

The dining comparison answers a narrower design question: does this authored connection remove this graph's access gap? Matched native captures explain the geometry, while connector closure and the unresolved entrance threshold provide useful negative controls. The graph is partial and separate from the service forecast. It does not establish crowd throughput, certified accessibility, safe guest guidance or additional sales.

This fits the useful part of the FOX concept: a coordinator can gather evidence, compare options and submit bounded requests to the systems that own the work. The application is FOX-inspired; installed FOX and an autonomous LLM park operator are not demonstrated. ERP, CMMS, workforce and ride controls should retain their respective authority. The twin provides shared asset identity, context and evidence rather than replacing those systems.

## The negative policy result matters

The [independent food-service evaluation](2026-10-19-evidence-and-policy-review.md) reproduced the accounting for 324 synthetic cases. Planner and simple rule chose identical schedules in 216. In the other 108, extra staff cost EUR56 per case; 52 of those cases had no waiting improvement. Doing nothing dominated the planner choice in 92 cases under that evaluator's modeled objectives.

Across the complete grid, the planner's mean difference from the rule was only 1.701 additional completed service visits, 28.883 fewer accumulated guest-minutes waiting and EUR18.667 extra labor. Those averages are not expected real outcomes or an ROI calculation. The evaluator omits minimum coverage, donor-team loss, setup disruption and replenishment cost; baseline superiority does not authorize understaffing.

The practical conclusion is to retain do-nothing and simple-rule comparisons, show marginal benefit beside cost, and obtain an operator's valuation and actual feasibility constraints before increasing planner autonomy. More agents or a more detailed scene do not resolve that missing evidence.

## Strongest next pilot

Use one ride, one duty-manager role, one read-only incident feed and a CMMS sandbox. Establish the real asset mapping, source timestamps, inspection state and work-order lifecycle first. Then compare the existing workflow with the direct incident interface on matched, held-out tasks, counterbalancing task order to limit learning effects.

Measure alert-to-correct-asset identification, alert-to-verified-order time, incorrect or duplicate orders, operator corrections and recovery from stale data or lost acknowledgements. Check whether the operator understands that an accepted order leaves physical completion unresolved. Agree useful improvement and error limits before collecting outcomes; report individual tasks and failures alongside summaries. A scripted reduction from seven steps to four is a promising interface change, not measured human productivity.

Advance to a narrowly authenticated real CMMS request only after the sandbox process is useful and its authorization, provider identity and retry reconciliation are established. Keep ride reopening and physical control with the established operating process. This pilot can test practical value without first building a park-wide crowd model.

## Keep, refactor or rebuild

**Keep the current modular architecture; do not rebuild it.** Accepted observations, pure planning, historical evidence, bounded workflows, spatial queries and native rendering have distinct responsibilities. Numeric and API correctness can be evaluated without a GPU. Separate immutable release and scene identities make the visual evidence inspectable.

Reviews found concrete defects and the team corrected them: observed heat constraints, hidden sensitivity harm, browser number normalization, stale readback provenance, unnecessary forecast prerequisites, and misleading completion/coverage boundaries. This is evidence for continued targeted review, not for a wholesale rewrite.

The necessary small tooling consolidation has begun: analyzer and deck now share the v2 evidence validator, retaining gaps, pauses, failures and source verification. Preserve that boundary and keep media dependencies outside the application. Add new connectors only when a named user decision requires them; avoid duplicating policy logic in the browser, renderer or multiple adapters.

## What remains unproven

Real operator usefulness, calibrated arrival/service forecasts, qualified staffing and donor coverage, reliable vendor writes, guest response to guidance, complete walkable geometry and economic return remain unvalidated. The real weather preview supplies separate model context; it does not make the synthetic park observations real. Public delivery would also require a deployment-specific assessment of identity, access control and operational ownership beyond these functional demonstrations.

The eight-hour exercise can establish the recorded checks, observation coverage and failures of its declared tracks. It cannot establish continuous uptime, production readiness, safety, causal savings or operator trust. Publish its reconciled evidence on those terms, then spend the next cycle obtaining the narrow operator and source-system evidence needed for the maintenance pilot.
