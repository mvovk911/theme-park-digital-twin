## User objective

Extend the operational twin toward a park manager agent: research FOX, identify
valuable decisions and what-if simulations, build the necessary APIs, and have
independent agents regularly challenge behavior and end-user value. Preserve
reviewable source, screenshots, research and progress in the public repository.

Working assumptions, pending owner feedback: a regional park operations manager;
synthetic action execution; real integrations researched and designed without
physical actuation. Prioritize incident response, guest waiting burden and feasible
resource allocation. Existing ERP/CMMS/BMS remain systems of record in a real pilot.

## Team and responsibilities

- Integrator: GPU runtime, application experience, API integration, release evidence
  and repository checkpoints.
- Research/build agent: primary-source research and isolated forward-simulation
  contracts/engine, using frozen accepted observations.
- Value reviewer: independent assessment of decision usefulness, assumptions,
  baselines, feasibility, uncertainty and maintainability.
- API operator: black-box HTTP client, failure/recovery checks, intervention versus
  baseline experiments and measured postconditions. Deterministic clients will be
  labeled as such; they are not represented as model reasoning.

Reviews happen at each integrated milestone and at least hourly during active
work. The operator's execution windows are coordinated so it cannot corrupt a
browser capture or another evaluator's experiment.

## Evidence standard

Report total guest-minutes waiting, served and unserved demand, resource feasibility,
energy/water quantities and adverse tradeoffs. An unweighted average queue length
can improve merely because a closed ride disappears; it is not the primary value
metric. Simulated benefits are model outcomes, not validated park savings.

Each experiment records input state/revision, scenario, assumptions, model version,
candidate actions, comparison baseline, quality status, timestamps and outcomes.
Distinguish API acceptance from a verified effect, and a synthetic effect from
real-world operation. Do not silently overwrite accepted source observations with
simulation output. A what-if branch must not mutate the live park.

## Scope boundaries

FOX-inspired does not mean NVIDIA FOX has been installed. Public availability and
component claims are checked against primary sources in the research documents.
The 3D scene supplies spatial context; it does not validate crowd, electrical,
hydraulic, ride-structural, emergency or weather models. Those need specialist
solvers, calibration and operational approval in a real deployment.

This run starts from repository commit `db86ca1` and the retained deployment at
`19cee1e`. New evidence will identify the actual deployed candidate. Runtime DBs,
credentials, provider inventory and transient logs remain outside Git.
